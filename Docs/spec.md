## 2. サイト構成

- ポータルトップ（`index.html`）にゲーム一覧をカード形式で表示し、カードをクリックすると各ゲーム画面（`gomoku.html` / `gogo-shogi.html`）に遷移する。
- 各ゲーム画面は「難易度選択 → 対局画面 → 結果モーダル（もう一度対局する / ポータルトップへ）」という共通の画面遷移パターンに従う。
- ヘッダーは全ページ共通で、ゲーム画面ではポータルトップへ戻る導線を表示する。

## 3. デザインシステム

要求仕様書のヒアリングに基づき「モダン・ミニマル」路線を採用。

- 背景: チャコール系（`#1c1f26`）、カード面: `#262a33` + 細いボーダー
- アクセントカラー: ゲームごとに切り替え（五目並べ=エメラルド`#3ddc97`、五五将棋=アンバー`#e8a33d`）
- 角丸: 8px、フラットでシャープなカード形状
- フォント: ニュートラルなゴシック体一本（`Hiragino Sans` / `Yu Gothic` 等のシステムフォントスタック）
- 今後ゲームが増えてもカードを追加するだけで一覧に反映される配列駆動の構造

## 4. 共通UI仕様

- **難易度選択**: 弱・中・強の3段階を共通コンポーネントで提供。両ゲームで見た目・操作感を統一。
- **結果モーダル**: 勝ち/負け/引き分けをメッセージ付きで表示し、「もう一度対局する」（難易度選択に戻る）「ポータルトップへ」の導線を提供。
- **ヘッダー**: ポータルトップへの導線を常時表示。

## 5. ゲーム1: 五目並べ（Gomoku）

要求仕様書の記載どおり実装。差分・確定事項は以下。

- 盤面15×15、5つ以上連続で勝利、禁じ手なし。既存Firestore実装は流用せず、盤面状態はブラウザ内Stateで完結。
- プレイヤーは黒（先手）固定、CPUは白（後手）固定。
- 難易度ごとのAI実装（実装時に確定した具体的な方針）:
  - **弱**: 「自分が置けば5連になる手」を必打、「相手が次に置けば5連になる手」を必ず阻止。それ以外は候補手（既存石の周農2マス以内）からランダム選択。
  - **中**: 連続数・両端の空き具合をスコア化する評価関数による1手先読み（貪欲法）。
  - **強**: 同評価関数＋ミニマックス法（αβ枝刈り）で4手先読み。候補手は既存石の周辺2マス以内、評価スコア上位8手に絞って探索空間を抑制。
### 4.4 オンライン対戦（Phase 2）

要求仕様書の付録（`gomoku_requirements.md`）はルームURL共有方式を想定していたが、実装時の相談により以下の方式に変更して実装した。

- ルームURLでの共有は行わない。**ルーム一覧から参加**するか、**ルーム番号（6文字コード）を入力して参加**するかのいずれか。
- ルーム作成時に**公開/非公開**を選択できる。公開ルームのみ一覧（Firestoreのリアルタイムクエリ）に表示され誰でも参加可能。非公開ルームは一覧に出ず、番号を知っている人だけが参加できる。
- プレイヤー名の入力は任意。ブラウザへの記憶（localStorage）は行わない。未入力の場合は「先手」「後手」と表示する。
- 対局が放置された場合に備え、ルームは作成から**3時間でFirestoreのTTL機能により自動削除**される（要Google Cloud ConsoleでのTTLポリシー設定、`Docs/README.md`参照）。
- 盤面ロジック（`checkWin`, `isBoardFull`, 盤面生成）はCPU対戦と共通のものをそのまま再利用。着手はFirestoreの`runTransaction`で「手番か」「空きマスか」を再確認してから書き込み、勝敗判定もクライアント側で行う（サーバーサイドロジックは持たない）。
- データモデル: `games/{roomId}`（`board`はFirestoreがネスト配列を扱えないため225要素のフラット配列で保存し、アプリ内では15×15の2次元配列に変換して扱う。詳細は`Docs/design.md`参照）。
- 五五将棋にも同じ設計思想でオンライン対戦を実装済み（詳細は6.1節）。

## 6. ゲーム2: 五五将棋（ごごしょうぎ / Minishogi）

要求仕様書5章の内容をそのまま実装。特に複雑なルールは実装時にユニットテストで正しさを担保した。

- 5×5盤、6種12枚の駒（王将/玉将・飛車・角行・銀将・金将・歩兵）、桂馬・香車なし。
- 成り: 敵陣は最も奥の1列のみ。王将・玉将・金将は成れない。飛車→竜王、角行→竜馬、銀将→成銀、歩兵→と金。
- 禁止事項: 二歩、打ち歩詰め、行き所のない駒（最奥段への歩打ち等）を実装・テスト済み。
- 勝敗判定: 詰み判定を実装。**千日手（同一局面4回出現）は先手の負け**、連続王手の千日手は王手をかけ続けた側の負け、という五五将棋特有ルールを実装（局面キー＋着手履歴から判定）。持将棋の判定ロジックは要求仕様書どおり未実装（投了ボタンで終局を促す）。
- 投了ボタンを実装。CPUは評価値が著しく劣勢（駒得換算で概ね飛車を失う規模以上）と判断した場合に投了する。
- プレイヤーは先手（王将）固定、CPUは後手（玉将）固定。
- 難易度ごとのAI実装（実装時に確定した具体的な方針）:
  - **弱**: 合法手（王手放置となる手は合法手生成の時点で除外済み）からランダム選択。
  - **中**: 駒得＋簡易玉安全度評価によるミニマックス（αβ枝刈り）で3手読み。
  - **強**: 駒得＋玉安全度＋盤面支配（可動域）を含む評価関数によるミニマックス（αβ枝刈り）で4手読み。
- 画面構成: 5×5盤面、持ち駒表示（先手・後手それぞれ）、手番・王手表示、成り選択ポップアップ（敵陣に関わる手を指した際、成る/成らないの両方が選べる場合のみ表示）。
- 駒の表示は漢字1文字（王/玉/飛/角/銀/金/歩/竜/馬/全/と）。後手の駒は視認性のため180度回転して表示。

### 6.1 オンライン対戦（Phase 2）

五目並べのオンライン対戦（4.4節）と同じUI・運用方針（ルーム一覧＋番号参加、公開/非公開、名前任意、3時間TTL）をそのまま踏襲している。データが複雑になる分、以下の点が異なる。

- Firestoreのコレクションは`shogiGames`（五目並べの`games`とは別）を使用。スキーマが大きく異なるため分離した。
- 盤面（5×5）に加えて**持ち駒（hand）**もFirestoreに同期する。取った駒は即座に相手側の持ち駒欄から消え、自分側に反映される。
- **成り/不成りの選択**はCPU対戦と共通のポップアップ（`src/games/gogo-shogi/ui/promotionPrompt.ts`）をそのまま使用。ローカルで選択を確定させてから着手として送信するため、追加の同期は不要。
- **千日手判定**のため、着手履歴（`HistoryEntry[]`）をルームドキュメントに保持し、既存の`checkRepetition`（ロジック層で実装・テスト済み）をそのまま利用する。
- 決着理由（`winReason`）として「詰み」「投了」「千日手」「連続王手の千日手」の4種類を管理し、結果表示のメッセージを出し分ける。
- プレイヤーは先手（王将）固定、参加者が後手（玉将）固定（CPU対戦と同じ役割分担）。

## 7. ゲーム3: 〇×ゲーム（三目並べ）

`Docs/todo.md`の要望により追加。要求仕様書には記載がないため、既存2ゲームと同じ設計思想（難易度選択→対局→結果、ルール説明画面）で新規に仕様化した。

- 3×3盤、2人が交互に○×を置き、縦・横・斜めのいずれかに自分の記号を3つ連続で並べたら勝ち。禁じ手なし。盤面が埋まって決着しなければ引き分け。
- プレイヤーは○（先手）固定、CPUは×（後手）固定。
- 難易度ごとのAI実装:
  - **弱**: 即勝ち・即阻止を優先し、なければランダム。
  - **中**: 深さ2のミニマックス＋簡易評価関数。
  - **強**: 深さ9（盤面を使い切るまで）のフルミニマックス＋αβ枝刈り。3×3は状態数が小さいため事実上の完全読みとなり、最善手を指し続ければ引き分け以下にはならない（実装時にブラウザで検証済み）。
- CPU対戦のみ（オンライン対戦は今回スコープ外）。投了ボタン・ルール説明画面あり。

## 8. ゲーム4: オートリオ

`Docs/todo.md`の要望により追加。実在のボードゲーム「Otrio」の**基本ルールのみ**を実装し、マスタールール（異サイズ混在の3並び）は実装していない。

- 3×3盤。各マスには小・中・大のサイズごとに駒を1つずつ重ねて置ける（既に置かれた駒は取り除かれない）。各プレイヤーは小・中・大の駒を3個ずつ、計9個保有する。
- 勝利条件: (1) 同じサイズの駒が縦・横・斜めのいずれかに3つ並ぶ、(2) 1つのマスに自分の小・中・大の駒がすべて揃う（トリオ）。異サイズ混在の3並びは勝利条件に含めない。
- 両者の持ち駒（18個）をすべて使い切っても決着しなければ引き分け。
- プレイヤーは1P（先手）固定、CPUは2P（後手）固定。
- 難易度ごとのAI実装:
  - **弱**: 即勝ちできる手を優先。なければ相手の即勝ち手を検出し、同じマス・サイズに打てるなら阻止。それ以外はランダム。
  - **中**: 深さ2のミニマックス＋評価関数（ライン・トリオそれぞれの完成度をスコア化）。
  - **強**: 深さ6・候補手上位10手に絞ったミニマックス＋αβ枝刈り（同じ評価関数を使用）。
- 画面構成: 盤面（3×3、各マスに小中大の入れ子表示）、自分/CPUの持ち駒表示、持ち駒を選択してから盤面をクリックして着手する操作方式（五五将棋の持ち駒選択と同じ操作パターン）。
- CPU対戦のみ（オンライン対戦は今回スコープ外）。投了ボタン・ルール説明画面あり。
